# 研究与实验计划

更新日期：2026-10-28。定位：课程或学位研究项目。Proposal 截止：2026-11-24（北京时间）；最终报告截止时间待确认。

## 1. 已知约束与推荐方向

用户已确认：预算较低，本机使用 RTX 4070，必要时考虑租用 AutoDL 4090，没有领域专家标注支持。本机 `nvidia-smi` 进一步确认 GPU 为 RTX 4070 Laptop，显存总量 8188 MiB。8 GB 显存下的多图推理是否稳定，需要实测，不能按桌面版 4070 估算。

建议题目：**视觉输入缺失与退化对显微镜视觉语言模型可靠性的影响：基于 MicroVQA 的可复现实验研究**。

英文暂定题目：**Evaluating Microscopy Vision-Language Models under Missing and Degraded Visual Inputs on MicroVQA**。

主线为“视觉输入条件 → 回答正确性 → 置信度与选择性作答”。完成一个模型的可信实验闭环优先于扩展模型数量。首阶段不训练、不微调；第二个模型用于检验结果是否局限于单一 checkpoint，不作为 proposal 能否提交的前提。

此前设想的人工证据区域遮挡不列入必做实验：当前没有专家资源，随机框、显著性区域或模型自己提出的框均不能直接当作真实关键证据。现有区域遮挡代码保留，作为后续有可靠标注时的扩展接口。

## 2. 研究动机与贡献边界

MicroVQA 针对显微镜科研问答，包含专家理解、假设生成、实验设计等任务，并在构建选择题时处理语言捷径。它适合检验科学图像条件下的模型行为。[MicroVQA 原始论文](https://openaccess.thecvf.com/content/CVPR2025/papers/Burgess_MicroVQA_A_Multimodal_Reasoning_Benchmark_for_Microscopy-Based_Scientific_Research_CVPR_2025_paper.pdf)

视觉问答中的语言先验与视觉 grounding 已有较长研究历史，不能把“模型可能依赖语言”作为本项目独有发现。[VQA-CP](https://openaccess.thecvf.com/content_cvpr_2018/html/Agrawal_Dont_Just_Assume_CVPR_2018_paper.html)、[HINT](https://arxiv.org/abs/1902.03751)

多模态证据不足与弃答也已有直接相关工作，例如 2026 年的 MM-AQA 预印本。本项目不声称首次研究多模态弃答。[Knowing When Not to Answer](https://arxiv.org/abs/2604.14799)

本项目拟贡献：

1. 在固定模型、题目、提示词和输入处理下，对 MicroVQA 的缺图与图像退化进行配对评估。
2. 将性能变化与置信度、错误接受率、覆盖率放在同一分析中，区分“答错”“格式失败”“主动弃答”。
3. 交付能够从固定数据版本和预测文件重建结果的代码、配置、表格、图像与实验记录。

这是针对显微镜任务的实证研究与科研系统交付。是否具有进一步投稿价值取决于后续结果、相关工作覆盖和独立模型验证，不预先承诺新算法、性能提升或统计显著性。

## 3. 研究问题和可检验预期

| 问题 | 操作化比较 | 主要读数 | 可解释范围 |
| --- | --- | --- | --- |
| RQ1：图像输入带来多少收益？ | 同一个 VLM：原图 vs Text-only；问题和选项不变 | 配对准确率差、作答转移、无图仍答对比例 | 衡量给定协议下的图像输入收益；不能单独证明语言捷径或内部推理机制 |
| RQ2：图像细节退化时，模型表现如何变化？ | 原图 vs 两档模糊、两档降采样 | 准确率变化、组级置信区间、退化趋势 | 衡量具体图像操作下的敏感性；模糊不等价于真实显微镜采集故障 |
| RQ3：模型信心和选择性作答能否反映错误风险？ | 原图及退化条件下的强制作答置信度；独立的允许弃答协议 | 错误但高信心比例、风险–覆盖率、弃答/格式失败 | 检验错误识别和选择性预测；没有可回答性标注时不评价“应当弃答”的语义正确率 |

方向性预期可以写为：原图可能优于无图；强退化可能比弱退化损失更大；信心可能未随错误风险同步变化。这些是待检验假设。图像去噪、模型预处理和题目本身的信息冗余都可能产生非单调或零差异结果，必须如实报告。

**主终点建议只设一个**：锁定测试集上，强制作答协议下的 `accuracy(original) - accuracy(text_only)`。图像退化与置信度分析作为预先声明的次要分析，避免从多个条件中事后选出最漂亮的结果。

## 4. 数据与划分

官方数据卡当前列出 1042 个 test 样本，提供 `key_question`、`key_image`、多图列表、题目、选项、正确索引及任务字段。实际数量以固定 commit 的导出与审计结果为准。[官方数据卡](https://huggingface.co/datasets/jmhb/microvqa/blob/main/README.md)

先输出数据审计报告：样本数、图像组数、每题图数、尺寸分布、选项数、任务类别、重复图像、读图失败和缺失字段。当前导出器只保存少量 metadata；成像模态等分组如果没有可靠来源，不从图片外观自动猜测。

### 4.1 三类集合

| 集合 | 建议范围 | 用途 |
| --- | --- | --- |
| 调试 smoke set | 6–10 题，来自开发图像组，覆盖单图和多图 | 检查输入、GPU、输出解析；不作研究结果 |
| 开发/预实验集合 | 预留约 15%–20% 图像组；先选 50 题，必要时扩展到约 100 题 | 调整像素预算、提示词格式、退化强度和阈值；支持 proposal 可行性说明 |
| 锁定测试集合 | 剩余图像组；实际题数由分组决定 | 协议冻结后的主要结论，不用结果反复修改方法 |

上述数量是工作量目标，不是功效计算结论。使用固定随机种子保存显式 ID 清单，按 `key_image` 分组，审计相同图片是否跨组；发现跨组共享图像时合并相关组后再划分。尽量平衡任务类型和单/多图比例，无法完全平衡时记录分布。

这些是**本研究内部划分**，不是 MicroVQA 官方 train/validation/test。不得将其用于监督训练并仍宣称使用完整未见测试集。若最终同时给出完整 1042 题描述性结果，要单独标明开发样本已被查看，不能与锁定测试结果混称。

当前 `--limit` 只是取文件前 N 条，不能替代此划分。实现分组与 ID 选择是正式实验前的 P0 开发项。

## 5. 模型与低预算推理策略

主模型候选为仓库已有配置对应的 `Qwen/Qwen2.5-VL-3B-Instruct`，理由是可衔接现有适配器，并支持多图和输入像素范围控制；不是以“最新最强”为选择标准。[模型官方说明](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct)

实施顺序：

1. 检查本机 PyTorch/CUDA、Transformers 与模型版本的兼容性，固定模型 commit。
2. `batch_size=1`、无长链式输出，先用 64–128 个生成 token；根据 JSON 截断率冻结长度。
3. 接入并记录 processor 的像素参数、每题总图数、实际视觉 token/网格和峰值显存。官方存在像素范围控制不代表当前代码已经接通。
4. 若半精度加载或多图推理 OOM，评估受支持的 4-bit 量化或 CPU offload；量化格式、后端、计算 dtype 都必须进入配置和模型标识。不能把量化与非量化结果无区别混合。
5. 同一题在所有有图条件中使用同一预处理与像素预算，保留全部图像及顺序。不能为能跑而只留第一张图。下调像素上限会影响研究结论，要作为协议记录。
6. 只有本机持续无法完成必要多图输入、或测得总时长不合理时，才选择一次短期租用 4090。先在本机完成数据、脚本和缓存验证，再上云跑固定任务清单。

不保证 3B 在本机 8 GB 上能够无 offload 运行。若量化适配成本过高，可以更换为经官方说明确认支持多图、且通过小样本实测的更小 VLM；应在预实验阶段完成选择。第二模型的具体名称和费用在主模型可行性确定后再决定。

## 6. 实验矩阵

### 6.1 Proposal 前的最低可交付预实验

在同一组约 50 个开发样本上，使用一个真实模型完成：

| 编号 | 协议 | 条件 | 目的 |
| --- | --- | --- | --- |
| P0 | 强制作答 | 原图 | 建立可运行、可解析的基线 |
| P1 | 强制作答 | Text-only | 验证无图请求和配对比较 |
| P2 | 强制作答 | 一档高斯模糊 | 检查退化操作到实际模型输入的链路 |
| P3 | 强制作答 | 一档降采样后恢复尺寸 | 检查细节损失条件 |

共约 `50 × 4 = 200` 次样本推理，另留少量调试调用。这里的“推理次数”不是 API 费用或运行小时估计。输出真实准确率、解析成功率、耗时和峰值显存即可，不要求得到显著差异。

如果 11 月 13 日前还有余量，在相同开发样本原图上增加允许弃答协议。Proposal 可引用这些结果作为可行性证据，必须注明样本范围和协议仍在开发阶段。

### 6.2 Proposal 后的正式实验

| 实验 | 必要性 | 输入条件 | 分析 |
| --- | --- | --- | --- |
| E1 图像输入收益 | 必做 | 原图、Text-only | RQ1 主终点与作答转移 |
| E2 图像退化 | 必做 | 弱/强模糊、1/2 和 1/4 降采样后恢复原尺寸 | RQ2 趋势；复用 E1 原图预测 |
| E3 信心与选择性作答 | 基础统计必做；额外推理视余量 | 先用 E1/E2 强制作答 confidence；再选原图、Text-only、强退化运行允许弃答协议 | RQ3，分别标明协议 |
| E4 多图逐张移除 | 可选 | 多图题每次移除一张；不改变其余图片顺序 | 分析图片提供的增量信息；不称为专家关键证据定位 |
| E5 第二模型 | 可选，优先于新增复杂方法 | 重复锁定的 E1/E2 | 检查结论的模型特异性 |
| E6 随机区域遮挡 | 探索性 | 固定面积比例、多个随机位置 | 测试一般局部破坏；没有语义真值，不命名为 evidence masking |

主矩阵每个模型为 6 个强制作答条件。开发集合冻结后，不在正式测试集上筛选“更容易得到差异”的模糊参数。像素半径会受图像尺寸影响：建议新增 `sigma_fraction × min(width,height)` 的相对模糊强度，开发集用少量档位检查可见程度后固定。当前代码只有固定像素 radius，仍需开发。不要把两类退化的数值强度当作相同物理严重度。

### 6.3 两种作答协议

**强制作答协议**要求从选项中选择一个答案，并输出 confidence；未作答、越界或解析失败单独标记，不能通过解析器补成正确答案。主准确率比较在同一协议内进行。

**允许弃答协议**明确允许 `answer=null, abstain=true`。统计覆盖率和选择性准确率，不把其总体准确率与强制作答结果直接解释为视觉能力差异。当前提示词只有这一协议，新增双协议与记录 prompt hash 是必做项。

如果引用原论文模型分数作外部背景，需核对模型版本、预处理、提示词和输出判定。我们的结构化 confidence 协议与作者原评测不必相同，不能将分数差异直接写成复现失败或模型进步。

## 7. 指标、统计与解释

令 `c_i^k` 表示样本 i 在条件 k 下是否答对。主效应定义为：

`visual_gain = mean_i(c_i^original - c_i^text_only)`。

这是本研究的描述性差值名称，不是宣称新提出的公认评价指标。退化损失为 `mean_i(c_i^original - c_i^degraded)`。现有 `paired.py` 使用 `intervention - baseline`，报告层必须明确符号，不能直接把负值标成 gain。

| 读数 | 计算或要求 | 避免误读 |
| --- | --- | --- |
| 总体准确率 | 正确 / 全部预定样本；单独显示模型未作答和解析失败 | 不只筛选原图答对的题作为主分析 |
| 作答转移 | 两条件均对、原图对另一条件错、原图错另一条件对、均错 | 无图答对不等于语言作弊；可能有文本信息冗余 |
| 置信度校准 | 自报 confidence 的 ECE 与 correctness Brier，显示有效 confidence 数和分布 | 自报 confidence 不是 token 概率；不能直接比较不同模型的原始信心高低 |
| 错误但高信心比例 | 例如错误且 confidence≥0.8 的有效预测数 / 全部样本；阈值预先冻结 | 同时报告 confidence 缺失率，不将缺失信心当作低信心 |
| 风险–覆盖率 | 对强制作答记录按 confidence 阈值接受或拒绝；原图优先 | 仅在置信度可用的范围绘制，并显示相对于全部样本的最大覆盖率 |
| 主动弃答 | 有效主动弃答数 / 全部样本；另列格式失败率 | 退化不自动使题目不可回答，不能把“所有遮挡样本”标成应弃答 |

选择性预测以风险和覆盖率的权衡为基础。[Selective Classification for Deep Neural Networks](https://proceedings.neurips.cc/paper/2017/hash/4a8423d5e91fda00bb7e46540e2b0cf1-Abstract.html)

对于退化后的图像，原始标签仍可用于“相对于原任务答案的保持程度”，但严重退化可能消除可判别信息。没有新标注时，不能将该分数等同于退化样本的客观可回答性，也不能评价弃答是否符合领域专家判断。

统计约定：

- 按相同 ID 对齐预测，严格核对标签、数据版本、分组和作答协议。
- 主要 CI 使用按图像组重采样的 paired bootstrap；固定 seed，正式报告建议 5000 次，并报告问题数和独立组数。
- 多次随机干预与多次模型采样不是独立题目：先在每题内汇总，再保留图像组层次做分析。
- `perturbation_seed`、`generation_seed`、`bootstrap_seed` 应分开。不能同时换遮挡位置和解码随机性后只归因于遮挡。
- 当前 McNemar 未处理共享图像相关性，只作补充，不作为主要显著性依据。主报告以效应量和组级 CI 为中心。
- 预先指定主比较；其他多个比较若给出显著性结论，需要合适的组级检验及 Holm 等多重比较控制。未实现前将其作为探索性 CI，不用星号包装结论。
- 未检测到差异不等于等效。若 CI 很宽，结论应为不确定；不能通过不断增加条件或筛选样本制造结果。

## 8. 预算与规模选择

设锁定测试样本数为 N，一个模型的六条件主矩阵为 `6N` 次推理。额外三条件允许弃答矩阵为 `3N`。第二模型会增加另一份工作量；实际复用取决于请求、prompt、图像处理和模型版本完全一致。

| 档位 | 建议用途 | 计划工作量 |
| --- | --- | --- |
| Proposal 最低档 | 11 月 24 日前 | 1 模型 × 50 开发题 × 4 条件 = 200 次，另加调试 |
| 最终最低可交付档 | 本机时间有限时 | 锁定、按组抽取约 200–300 题 × 1 模型 × 6 条件；不称完整 benchmark |
| 最终标准档 | 本机稳定、时间允许 | 剩余锁定测试集 × 1 模型 × 6 条件，补充选择性作答分析 |
| 扩展档 | 核心结论和交付已完成 | 第二模型或多图逐张移除，二选一优先 |

200–300 题是工程预算范围，不保证统计功效。最终按预实验的组数、组内相关性、差值波动估计 CI 宽度；若预算无法支持精确估计，应缩小结论。

运行时间必须由本机预实验估计，按单图/多图及各条件分别计时。预计总时长可用 `Σ 条件和图数层的待跑量 × 对应实测平均秒数 / 3600`，另计模型加载、数据处理和失败重试。云端支出按用户实际实例单价 × 使用小时估算；尚未确认金额上限，不在计划中虚构价格或自动购买实例。

## 9. Proposal 与最终结果的成功标准

Proposal 阶段应具备：明确问题、核对过的相关工作、无专家标注也能完成的实验协议、真实小样本可行性证据、风险与时间计划。没有显著发现不影响写出合格 proposal。

最终最低成果为：一个模型、一套冻结协议、一份有明确样本范围的结果、效应量与不确定性、失败/资源限制分析、可重建表格和图表的交付包。模型间泛化、语义关键证据、正确弃答或内部因果机制，只有新增证据支持时才进入结论。
