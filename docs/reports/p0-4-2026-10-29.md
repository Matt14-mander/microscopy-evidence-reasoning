# P0-4 双作答协议验收

日期：2026-10-29。P0-4 已完成：`forced_choice@1.0` 与 `allow_abstain@1.0` 接入提示词、解析器、配置、预测记录和共用缓存。使用本机 RTX 4070 Laptop 的 Qwen2.5-VL-3B NF4/BF16 验证；模型 revision 和 P0-3 预处理配置保持一致，没有使用云 GPU 或测试集预测。

## 实测结果

确定性选择开发题 331、346、831、548、427、156，分别包含 1、1、2、2、6、3 张图。每题运行原图与 Text-only，各执行两种协议，共 24 次真实模型调用。

| 协议 | 真实调用 | 执行成功 | 协议有效输出 | 主动弃答 | 请求耗时中位数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| forced_choice@1.0 | 12 | 12 | 12 | 0 | 6.56 秒 |
| allow_abstain@1.0 | 12 | 12 | 12 | 0 | 6.70 秒 |

无 OOM，无生成长度截断。加载模型约 25.88 秒；推理阶段峰值 PyTorch allocated 约 2.857 GiB、reserved 约 3.021 GiB。耗时和显存口径沿用 P0-3，缓存读取不计为新的 GPU 调用；桌面负载和生成长度可能影响耗时，不以此比较协议效率。

两协议对应同题同条件的图片哈希、网格、视觉 token 和 processor fingerprint 一致。Text-only 不携带图片。每个协议每道题的 prompt hash 保留在 manifest/预测缓存；本地遥测还记录套用 chat template 后的文本 hash。

两个协议刻意使用同一个新缓存目录：**首次 0 命中、24 次真实生成、24 个唯一 key；随后 24/24 只读重放成功**。重放逐项核对原始响应和 telemetry，没有再次调用模型。汇总器验证两协议 key 不重叠，模板/协议/prompt hash 一致，24 项预测形成完整配对。

允许弃答协议在这批题上仍全部作答，因此本次没有真实弃答行为的对比证据。固定响应单元测试验证：同一个合法弃答 JSON 在 allow_abstain 下有效，在 forced_choice 下属于协议无效输出，并且不计入主动弃答率。不能将这 6 题视为模型可靠性或 benchmark 准确率结论。

| 项目 | 值 |
| --- | --- |

| forced_choice 模板 SHA256 | `fa4beab38a63ab013c966e072ed79ae8b47aeb50ed38e275a0494b39a9c9285a` |
| allow_abstain 模板 SHA256 | `6f74662604b60202b61b48aa1e08a033207dd8afb5d9819e91deec1673373ceb` |
| 模型 revision | `66285546d2b821cf421d4f5eb2576359d3770cd3` |
| cache schema | `prediction-cache-2` |

协议名/版本、parser 版本、模板 hash、实际 prompt/hash 都进入缓存 identity。即使传入相同 prompt 字节，协议不同仍产生不同 key；版本或模板变更也会失效。读取时核对整个 identity，错误元数据不会被忽略。

## 实现与测试

49 项离线测试全部通过，包括：

- 已发布模板摘要固定、Unicode/JSON 花括号保持原样、未知协议/版本拒绝。
- 强制作答的弃答/空答案不能成为有效主动弃答；格式错误和协议违规分别记录。
- 重复 JSON 键、额外键、非有限 confidence、越界选项、非 null 弃答 confidence 被拒绝。
- 共用缓存目录的跨协议隔离、相同协议重放、篡改 identity 拒绝；原始无效响应保留。
- 普通运行器中强制作答违规计入 invalid_rate，允许弃答计入 abstention_rate，全部样本继续保留在准确率分母。

普通运行器通过 `--protocol-config` 选择协议；每次运行只汇总一种协议。未显式配置的旧调用默认 allow_abstain@1.0，新运行的 resolved config 会记录此选择。历史结果保持原状，不补写成已执行的新版本实验。
