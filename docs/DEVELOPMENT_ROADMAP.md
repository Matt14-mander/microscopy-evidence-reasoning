## 2. P0：Proposal 前必须完成

建议按下列顺序实施，每个任务在本机验收后再推进。不要同时引入新模型、提示词和大规模实验，避免无法归因的调试。

| 编号 | 工作项与建议落点 | 验收标准 | 依赖 |
| --- | --- | --- | --- |
| P0-1 | 环境诊断与真实模型 smoke；扩展 `src/models/local.py`、`configs/models/` | 单图、多图、Text-only 各跑通；记录 GPU、torch/CUDA、模型 commit、dtype、显存峰值及耗时；不得静默丢图 | 无 |
| P0-2 | 数据审计和分组；新增 `src/data/audit.py`、`src/data/splits.py` | 固定数据 revision；全量可读检查；保存开发/测试 ID 与图像组；交集为空；重复图像跨组有处理记录 | 无，可与模型准备交错进行 |
| P0-3 | 预处理与显存参数；扩展本地模型配置与请求记录 | 像素参数真正传入 processor；保存实际图像网格/尺寸；多图 OOM 可追溯；同题有图条件遵守同一预算 | P0-1 |
| P0-4 | 双作答协议；扩展 prompt、parser、config | forced_choice / allow_abstain 明确分开；无效输出仍保留；结果有 protocol_id / prompt hash；不同协议不串缓存 | P0-1 |
| P0-5 | 明确样本清单与预实验配置；扩展 runner，新增 `configs/experiments/pilot.json` | 按 ID 清单运行约 50 开发题；原图/无图/模糊/降采样完全配对；不依赖人工框 | P0-2、P0-3、P0-4 |
| P0-6 | 实际输入审计与退化检查；扩展 transforms，增加 preview 工具 | 可查看原图、研究预处理图、退化图和 processor 信息；证明干预未被后续重采样抵消；图像顺序一致 | P0-3 |
| P0-7 | 预实验报告与基本差值图 | 从真实预测生成样本/组数、准确率、解析失败率、配对差、耗时和显存表；自动标注开发集和模型版本 | P0-5、P0-6 |

P0-1 如果需要量化，先验证对应库在当前操作系统、GPU 驱动和 Transformers 版本上的支持，保存实际安装约束；不要在 Windows 上为非必要加速库耗尽 proposal 准备时间。设备切换或租用实例不是默认动作。

### Proposal 前的测试重点

- 分组不交叉、固定种子结果稳定、ID 缺失和重复时报错。
- 模型请求保留多图顺序；Text-only 不携带图像；标签不进入 prompt。
- 协议改变使缓存失效，forced_choice 下的空答案不变成主动弃答成功。
- 像素限制进入实际 processor；超限和 OOM 记录可定位到样本与配置。
- 干预不改变原始输入，结果图展示真实变换，差值正负号一致。

单元测试验证逻辑，少量真实 GPU smoke 验证适配器；GPU 测试单独标记，不放入必须下载大模型的普通 CI。

## 3. P1：Proposal 后完成主实验和最终报告

| 编号 | 工作项 | 完成判据 |
| --- | --- | --- |
| P1-1 | 正式协议冻结与实验 registry | 固定模型 revision、prompt、数据 split、图像预算、退化强度、主比较、输出 schema；记录一次 protocol release |
| P1-2 | 稳健运行和独立随机种子 | `generation_seed`、`perturbation_seed`、`bootstrap_seed` 分离；失败样本单独记录和重试；重启不丢失已完成结果；不将基础设施失败计为弃答 |
| P1-3 | 六条件主实验 | 锁定样本全部条件齐全；不因模型答错剔除；基础设施失败有最终处理记录；输出可以被独立审计 |
| P1-4 | 置信度与选择性预测 | 高信心错误率、risk–coverage、可用 confidence 比例；所有阈值在开发集确定；主动弃答与后处理拒答分开 |
| P1-5 | 更完整的配对统计 | 按图像组 CI；按任务与单/多图描述；主比较明确；可选比较支持显式 reference_condition；多个随机副本不当作独立样本 |
| P1-6 | 缓存与溯源精细化 | 推理 fingerprint 覆盖输入/模型/processor/prompt，分析代码版本单独记录；修改绘图不强制重跑 GPU；旧 schema 不误读 |
| P1-7 | 科研图表与交付导出 | 主表、差值图、退化图、校准图；从预测文件重建而无需模型或网络；发布目录有校验和和复现命令 |

正式运行发生 OOM 时，优先在冻结的统一方案下补跑。若必须改变像素预算，应作为新的运行版本统一评估，不只给失败条件换成更小图片。无法补全的题必须显式报告，不能静默从某个条件的分母消失。

## 4. P2：有余量再做

推荐顺序：第二模型的小规模复核 → 多图逐张移除 → 输入预算敏感性 → 随机区域鲁棒性。只有具备可靠领域标注后，才重新考虑语义证据区域、匹配语义对照及证据充分性判断。

暂不列为必做：LoRA/全量微调、多智能体、大规模自动标注、新建完整 benchmark、复杂可视化前端、十几个模型榜单、训练一个新的 confidence 模型。它们增加开发和验证成本，但不是当前研究问题成立的必要条件。

可选的轻量扩展是开发集阈值选择或温度标定，与原始置信度做风险–覆盖率对比；不能在测试集上挑阈值，也不将简单后处理包装成未经对照的新算法。

## 7. 每次实验的完成定义

“脚本跑完”不足以视为实验完成。应同时满足：样本/条件清单完整、模型与协议版本可定位、数据 split 一致、原始输出与错误状态存在、指标分母正确、图表有样本数和来源、结论不超过证据范围。

P0-1/P0-2 已完成。下一次实际开发建议推进 **P0-3 的剩余预处理审计和 P0-4 双作答协议**，再进行约 50 开发题的四条件 pilot。
